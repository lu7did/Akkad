# Hive 0.2.19 — CPU affinity
Base: 0.2.18. Optional per-engine YAML `core: n` (nonnegative integer, default 0). Only local UCI processes receive affinity, before handshake and calibration. CPU IDs are logical and selected from Hive's permitted mask; allocations are disjoint among successfully pinned processes. Partial allocation warns; zero available or unsupported platform falls back to unrestricted execution, which can share CPUs. No OS-wide isolation. Windows uses native process affinity within the available processor mask (not multi-group scheduling); Linux pins existing threads. macOS falls back with warning. No extra dependencies. Internal Threads/--cores unchanged. Clones inherit requested core count and independently reserve CPUs. Reservations released after process exit; existing affinities are not redistributed dynamically. No YAML overwrite. Example: add `core: 1` to each local Stockfish definition; set its existing UCI options Threads: 1 if desired. Linux real child affinity verified; Windows not executed here. Existing 17 resource tests plus two affinity tests pass.
